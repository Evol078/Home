# Domain Docs

## Before exploring

Read root `GLOSSARY.md` when present and relevant decisions in `docs/adr/`. This repository uses a single-context layout. If `GLOSSARY-MAP.md` is introduced, follow its pointers for the relevant context.

When these files are absent, proceed silently. The domain-modeling skill creates them when vocabulary or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terminology in issues, proposals, code and tests. If a term is absent, check whether the project already has a name before proposing a new one.

If a proposed change contradicts an ADR, identify the ADR and explain why the decision needs to be reopened.
